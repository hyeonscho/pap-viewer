Luna에서 입력 설명만 바꿔 V3와 같은 12회를 다시 실행했다. 일부 concept 조합은 달라졌지만, 픽셀을 잘못 읽는 문제까지 해결되지는 않았다.

핵심 메시지

  • 창 밖 회색과 사각 경계가 가림 처리라는 설명만 교체했다.
  • MNIST 순차에는 밝은 획 + 세로 방향처럼 모양과 속성을 나누어 적용한 예가 생겼다.
  • Fashion 순차의 표현 증가는 대부분 단일 concept 재사용이며, 조합 능력 향상을 뜻하지 않는다.
  • 좌우·방향·명암 반전·열린 곡선과 닫힌 고리를 혼동하는 오류가 남았다.
  • 전부 검정인 창에 가로 선 세 개가 있다고 설명한 사례도 있어, mask 설명 누락만으로 기존 오류를 모두 설명할 수 없다.
  • 한 번에 넣는 조건에서는 선택한 근거가 앞쪽에 더 몰렸다. 이것만으로 뒤쪽 입력을 안 봤다고 단정할 수는 없다.

무엇을 고정하고 무엇을 바꿨나

MNIST와 Fashion-MNIST 각각 원본 210장, 관찰 1,050개. 같은 PNG bytes와 순서로 1,050개 한 번과 210개씩 다섯 번을 실행했다. 원본 28×28, 보이는 창 8×8, 창 밖 값 128을 유지했다. CORE·schema·누적 catalog 규칙·model·effort·timeout도 그대로다. 각 조건은 빈 catalog로 시작했고 순차에서는 V4 자신의 이전 정의와 review notes만 받았다.

교체한 입력 설명 · 한국어
각 이미지는 28×28 grayscale 원본에서 8×8 영역만 보이게 하고 나머지를 가린 이미지다. 창 안의 픽셀은 원본 값을 그대로 유지하며, 창 밖은 원본 내용과 관계없이 모두 회색(픽셀 값 128)으로 덮었다. 창 밖의 회색과 관찰창의 사각형 경계는 가림 처리로 생긴 것이므로, 원본의 배경이나 물체 모양으로 해석하지 마라. 창 안에도 실제 값이 128인 픽셀이 있을 수 있으므로, 회색이라는 이유만으로 가려진 영역이라고 판단하지 마라.
실제 공통 prompt 전체 · English
You are an agent that discovers reusable visual concepts from observations.

Compare recurring structures and the features that vary across observations. Define each concept around one independently reusable visual factor.
Separate a shared structure from attributes that can vary while that structure remains recognizable. Reuse the same attribute concept across different compatible structures when the observations support it.
Check each proposed definition by asking: if one feature changed while the others stayed the same, which concept should change and which concepts should remain reusable? Use this question to examine definitions, not as evidence that an unseen variant exists. Record uncertain separations in review_notes.
Express varied observations through combinations of a compact set of concepts while preserving meaningful visual distinctions. Do not split a factor into fragments that have no clear independent visual meaning.
Output concept definitions separately from expressions that combine those concepts. Do not register a new concept merely because a structure appears with a particular combination of attributes.
For each concept, provide a name, a short definition, every patch number actually used as evidence, and a description of what is visibly present in each cited patch. State what the concept defines and which other features are outside its definition.
For each compositional expression, provide its supporting patch number, the concepts used, their roles, and their relationships. Explicitly state which part each attribute describes and which parts each relationship connects.

Input and output format:
Each image is a 28x28 grayscale original with only an 8x8 region left visible and the rest masked out. Pixels inside the window retain their original values; outside the window, all pixels are replaced with gray (pixel value 128), regardless of the original content. The gray exterior and the rectangular window boundary are artifacts of masking, so do not interpret them as the original image background or object shape. Pixels inside the window may genuinely have value 128, so do not identify a region as masked merely because it is gray. No separate mask, coordinates, source identities, or class labels are supplied. Describe visible evidence; do not assume hidden continuations.

Return English JSON with new_concepts, expressions, and review_notes. Each new concept has id, name, definition, composition, and examples. Use review_notes for unresolved overlap or proposed revisions to earlier concepts, or an empty array.
composition contains parts (each with a unique role and concept_id) and combination (a short explanation of how those parts combine). Referenced IDs must exist in this response or the prior catalog. For an atomic concept use empty parts and an empty combination. Do not create circular references.
Prefer one reusable factor per definition. A named composite is appropriate only when observed examples support a recurring arrangement whose defining content is the relationship among parts. State that relationship and reference its constituent concepts. Do not create a named composite solely to attach particular attribute values to a structure. Do not split a factor further when the proposed fragments have no clear independent visual meaning. There is no fixed concept-count cap or predefined list of primitives.
examples contains every current patch actually used as evidence, each with batch, patch, and observation. observation must describe what is visibly present, not just give a filename. A patch can support multiple concepts. This is discovery evidence, not full labeling of all patches against all concepts. Uncited patches are unassessed. Do not relabel the prior catalog.
expressions contains illustrative uses of the discovered concepts on current patches. Each expression has batch, patch, observation, parts, and combination, with no new concept ID or name. Use one or more parts, each with a unique nonempty role and a concept_id from this response or the prior catalog. The same concept can appear in different roles. Describe the visible observation and how the parts relate in combination. Expressions may reuse existing concepts without proposing any new concept. Do not enumerate every patch-concept match. Expressions are archived separately and do not become definitions or historical catalog context.
Identify distinct part instances by role. In combination, explicitly state which role each attribute applies to and which roles each relationship connects; reusing one concept for multiple instances does not make those instances the same part.

별도 concept 금지 목록이나 끝점 규칙은 넣지 않았다. 창 밖을 관찰하지 않았다는 설명이 실제 image perception을 교정하는지 보는 재실행이다.

mask_artifact: 보이는 모양이 창의 사각 외곽에 의존하는 기록이다. V3 36/149, V4 29/192였다. 검정 픽셀 자체를 맞게 설명했어도 그 사각형이 원본 물체 모양이라는 근거는 없다. 이 flag와 픽셀 설명 오류는 별개다.
