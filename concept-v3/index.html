정의는 발견한 concept이고, 표현은 그 concept을 관찰에 적용한 예입니다. 두 기록의 근거를 따로 표시합니다.

입력 방식

실험 데이터를 불러오는 중입니다.

큰 한국어 문장은 영어 정의의 핵심을 풀이한 설명입니다. 작은 영어는 모델 원문이며, 이미지와의 일치 여부를 새로 판정한 정답은 아닙니다.

실제로 모델에 넣은 28×28 PNG를 확대했습니다. 픽셀 값은 그대로이며 8×8 밖은 밝기 128로 가려져 있습니다.

밝기는 일부 분리됐고, 모양과 방향은 여전히 묶여 있습니다

Fashion-MNIST 순차에서는 밝음·어두움이 별도 정의로 나왔습니다. B1 #2는 나란히 쌓인 가로 선과 어두움을 조합했습니다. 한편 MNIST에는 Bright vertical stroke와 Bright horizontal stroke가 별도 정의로 남았습니다. 원하는 모양·속성 분리를 충분히 달성했다고 보지는 않으며, 아래에는 모델의 정의와 근거를 그대로 보존했습니다.

02 / V2와 비교

같은 관찰에서 나온 정의와 표현

각 dataset은 원본 210장과 원본당 5개 관찰을 사용합니다. 같은 1,050개 관찰을 한 번에 주거나 210개씩 5회 주었습니다. 각 행은 독립 catalog이며 V3는 빈 catalog에서 시작했습니다.

Dataset · 입력V2 정의V3 정의V3 표현part 2개 이상

같은 concept을 서로 다른 역할로 여러 번 참조할 수도 있습니다. 정의 수나 part 수만으로 모양과 속성의 분리 성공을 판단할 수는 없습니다.

03 / 바꾼 지시

한 concept에 따로 재사용할 수 있는 한 특징

V2의 기준

따로 재사용할 수 있는 요소를 분해하고 정의와 관찰 표현을 나눴습니다. 다만 무엇을 별도로 나눌지에 대한 기준은 느슨했습니다.

V3에서 명시한 기준

공통 구조가 유지되는 동안 변하는 속성을 별도 concept으로 발견하도록 했습니다. 각 속성이 어느 부분을 설명하는지도 표현에 명시하도록 했습니다.

한 특징만 바뀌었을 때 나머지 concept을 그대로 쓸 수 있는지 점검합니다. 이 질문은 정의를 검토하는 기준이며, 보지 않은 변형을 관찰 근거로 쓰라는 뜻은 아닙니다. 구체적인 concept 이름·개수는 지정하지 않았습니다.

특정 모양에 속성을 붙인 조합은 expression으로 남기도록 했습니다. 별도 composed concept은 반복 관찰된 부분 사이의 관계를 정의하는 경우로 좁혔습니다. Schema·validator·순차 전달 방식은 V2와 같습니다.

각 행의 전체 입력은 1,050개입니다. 정의 근거와 표현 근거는 겹칠 수 있습니다. 모든 입력에 모든 concept의 존재 여부를 표시한 전체 labeling은 아닙니다.
Dataset · 입력V2 정의 근거V3 정의 근거V3 표현 근거V3 합집합

05 / 조건과 검증
V2와 같은 입력·실행 조건
  • 원본 420장·관찰 2,100개의 PNG bytes와 순서가 V2와 같습니다. 두 입력 스케줄의 첨부 횟수 합계는 4,200개입니다.
  • 같은 mlml1 구독 backend와 executable을 사용했습니다. Model·effort·timeout 1,800초·response 제한 2 MiB·실행 인자가 같습니다.
  • 12회 prompt·schema·응답·누적 catalog와 모든 expression 참조·근거 연결을 대조했습니다.

Cached input·reasoning output은 합계에 다시 더하지 않았습니다. 금액은 기록되지 않았습니다. 출력 내용이 달라 시간 차이를 latency 개선으로 해석하지 않습니다.


관찰한 출력의 한계
MNIST 순차의 첫 정의는 회색 배경 속 어두운 정사각형을 대상으로 삼았습니다. 관찰창 자체의 외형이 concept에 포함된 사례입니다. 또한 MNIST 한 번 입력 A_C006의 영어 정의에는 존재하지 않는 “patch 0”이 있지만, 구조화된 근거 목록에는 patch 9·8·30이 있습니다. 사이트의 근거 연결은 구조화된 목록을 따르며 영어 원문은 고치지 않았습니다.
Full labeling, semantic GT, detector 생성, held-out 평가는 하지 않았습니다. 올바른 역할 참조나 JSON 형식만으로 시각적 의미의 정확성을 보장할 수는 없습니다.
